$ llm-capacity-planner zai-org/GLM-5.3 --tokens 268k --users 200

Summary
  Recommendation: 5 servers with 8× NVIDIA B300 SXM each serve 200 users with requests of up to 268k tokens (≈ 210,000
      words ≈ 410 pages; 134k on average): ≈ 40 users per server. Each server runs 2 copies of the model, and a load
      balancer (a router in front of the servers) spreads the users across them. Caution: each server runs at 100% of
      its guaranteed capacity, so waits grow fast with more traffic: one more server leaves headroom.
  Alternative: 7 servers with 8× NVIDIA B200 SXM each (≈ 30 users per server). Caution: each server runs at 95% of its
      guaranteed capacity, so waits grow fast with more traffic: one more server leaves headroom.
  Not enough: RTX PRO 6000 Server, L4, L40S, A100 and H100, even with 8 GPUs in one server; RTX A6000, RTX 6000 Ada, RTX
      PRO 6000 WS, RTX PRO 6000 Max-Q and consumer cards, even with 4; GH200, even with 2.
  Speed for each user: writing about 35 words per second (18 to 52; 46 tokens/s); with everyone busy the first words
      appear after about 3.8 s, and a full 268k-token request alone is read in about 9.4 s (1 token ≈ 0.75 words).
  Confidence: memory high (±2.5%); writing speed medium (±49%); reading time low, not precise enough to decide (more
      than ±50%); user count medium (±49%). Plan on the guaranteed figures.

Technical detail
GLM-5.3 at 268k tokens, fp8 KV cache: serves users from 4× B300 SXM (1 model on 4), or 8× B200 SXM (1 model on 8). For
200 users (10% active ≈ 20 concurrent requests) you need 5 servers of 8× B300 SXM (2 copies × 4), or 7 servers of 8×
B200 SXM (1 model on 8): 40 users guaranteed, 80 likely per server, at 46 tok/s (23 to 69, ±49%, estimated) each.
Scenario "documents": each request brings 134k new tokens to read and generates 500; at least 20 tok/s per user. For a
chat (the conversation stays in the cache) use --prompt-cache 80.

Users: total = concurrent requests ÷ 10% active at once (--active); each gets ≥20 tok/s and the first token within 10 s
(or, if longer, twice the wait for the first words of one typical request alone: half the context, less what the prefix
cache holds).
Users include AI agents. Splitting work across parallel agents or subagents gets it done sooner, but each one is a
concurrent client: 5 subagents count as 5 users. Agents are usually active all the time and send long contexts, so raise
--active and --tokens for agent workloads.
Accuracy: exact = computed; measured = this model on this card; calibrated = fitted on measurements of this card or of
the same model type (N points); estimated = calibrated on other cards, not verified, or extrapolated; not precise enough
to decide = ±50% or more, or a case not covered.
Speed basis (vLLM 0.31.0) of the cards shown: estimated: mla FP8 not verified with vLLM, vLLM 0.31.0 (43 points).
Weights: exact as the sum of the tensors; for FP8 × MLA vLLM measured up to +2.6% more, counted in the fixed costs.
