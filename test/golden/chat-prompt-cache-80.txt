(1) partly supported: Block-scaled FP8 GEMMs (FlashInfer block-scale = SM90 only, DeepGEMM = SM90/10x/12x, CUTLASS
    blockwise = CC >= 9.0) all reject these archs, so MarlinFP8ScaledMMLinearKernel (weight-only W8A16) is chosen, even
    on Ada which has FP8 tensor cores. FA2 does not support fp8 KV, so vLLM selects another attention backend
    (FLASHINFER for most models, with Q in bf16). There are open bugs on this path: with pip and no nvcc, FlashInfer is
    selected but does not compile (crash 'Could not find nvcc'), and with checkpoints that have q_scale the output is
    wrong. Workaround: --attention-backend TRITON_ATTN (source:
    https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/kernels/linear/__init__.py#L455-L467)
(2) TP 2 on cards without NVLink or P2P: every all-reduce goes through CPU memory over PCIe (slower; needs x16 slots and
    an adequate power supply)
(3) TP 4 on cards without NVLink or P2P: every all-reduce goes through CPU memory over PCIe (slower; needs x16 slots and
    an adequate power supply)
(4) partly supported: DeepGEMM (enabled for the SM12x family) is tried first, with CUTLASS blockwise sm120 compiled as
    fallback. An open issue reports DeepGEMM aborting at weight load on SM120 ('Unknown SF transformation') up to August
    2026 nightlies; v0.31.0 pins a newer DeepGEMM fork built for 12.0f, but no report confirms the fix. Workaround:
    VLLM_USE_DEEP_GEMM=0 forces the CUTLASS blockwise SM120 kernel (verified as working with correct output in #47436).
    It starts (FlashInfer with CUDA 13 and head_k_dim 128, otherwise Triton FLA), but there is an open bug on RTX PRO
    6000: hybrid GDN NVFP4 models crash after ~7-8 minutes under load with CUDA graphs enabled (0.26-0.28, not verified
    on 0.31). Workaround: --enforce-eager. Workaround: --attention-backend TRITON_ATTN (source:
    https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/platforms/cuda.py#L709-L715)
(5) with 1 GPU the model fits, but nobody is guaranteed 20 tok/s of writing: 2 GPUs serve someone
(6) TP 4 over PCIe (no NVLink): all-reduces slower than over NVLink
(7) with 1 GPU the model fits, but the memory left after the model holds no full-length request with its safety margin:
    2 GPUs serve someone

Memory per GPU with one request of 32k tokens (≈ 25,000 words ≈ 49 pages): the model's weights and its conversation
memory (KV cache) are computed exactly, the engine's fixed costs are estimated. Margin = room left for more
conversations after that request. Card memory = what CUDA reports (the engine's usable memory; nvidia-smi shows a little
more).
Users: total = concurrent requests ÷ 10% active at once (--active); each gets ≥20 tok/s and the first token within 10 s
(or, if longer, twice the wait for the first words of one typical request alone: half the context, less what the prefix
cache holds).
Accuracy: exact = computed; measured = this model on this card; calibrated = fitted on measurements of this card or of
the same model type (N points); estimated = calibrated on other cards, not verified, or extrapolated; not precise enough
to decide = ±50% or more, or a case not covered.
Speed basis (vLLM 0.31.0) of the cards shown: estimated: hybrid FP8 not verified with vLLM, vLLM 0.31.0 (43 points);
measured on RTX 5090 with vLLM 0.31.0: Qwen3.8-27B FP8 (4 layers, 64K to 1M) and NVFP4 (16 layers, 1K to 128K); 23
points, on Windows / WSL 2 (23 points).
Weights: exact as the sum of the tensors; for FP8 × hybrid vLLM measured up to +3.3% more, counted in the fixed costs.
Multimodal model: with --text-only (vLLM --language-model-only) the vision encoder is not loaded.
