(1) fits in memory but the engine does not start: Pipeline parallelism does not work (wrong output, counted as not
    starting): On CUDA the registry entry resolves to DeepseekV32ForCausalLM (a DeepseekV2ForCausalLM subclass with
    SupportsPP), so pp>1 starts, but the PP handoff carries only hidden_states and residual while GLM-5.3 layers reuse
    the previous layer's indexer top-k (index_topk_freq 4); a stage that starts on a reusing layer (the default pp=2
    boundary is layer 39) reads a stale top-k. Open PR #59961 measured GSM8K 0.879 vs 0.908 for pp2 tp2 and showed
    VLLM_PP_LAYER_PARTITION=38,40 (boundary on a fresh-top-k layer) restores accuracy. Workaround:
    VLLM_PP_LAYER_PARTITION=38,40 puts the stage boundary on a layer that computes a fresh top-k (open PR #59961
    measured it restoring accuracy at pp=2). (source:
    https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/models/registry.py#L121-L121)
(2) at the limit: the request fits, but not the 21 GiB per GPU that sparse attention needs beyond 128K tokens while it
    reads a long prompt (seen on the reference GPU); and nobody is guaranteed 20 tok/s of writing
(3) sparse attention beyond 128K tokens: reading a 262K prompt, vLLM 0.31 used about 21 GiB more GPU memory than it had

Memory per GPU with one request of 1M tokens (≈ 790,000 words ≈ 1,600 pages): the model's weights and its conversation
memory (KV cache) are computed exactly, the engine's fixed costs are estimated. Margin = room left for more
conversations after that request. Card memory = what CUDA reports (the engine's usable memory; nvidia-smi shows a little
more).
Users: total = concurrent requests ÷ 10% active at once (--active); each gets ≥20 tok/s and the first token within 10 s
(or, if longer, twice the wait for the first words of one typical request alone: half the context, less what the prefix
cache holds).
Users include AI agents. Splitting work across parallel agents or subagents gets it done sooner, but each one is a
concurrent client: 5 subagents count as 5 users. Agents are usually active all the time and send long contexts, so raise
--active and --tokens for agent workloads.
Accuracy: exact = computed; measured = this model on this card; calibrated = fitted on measurements of this card or of
the same model type (N points); estimated = calibrated on other cards, not verified, or extrapolated; not precise enough
to decide = ±50% or more, or a case not covered.
Speed basis (vLLM 0.31.0) of the cards shown: estimated: mla FP8 not verified with vLLM, vLLM 0.31.0 (43 points).
Weights: exact as the sum of the tensors; for FP8 × MLA vLLM measured up to +2.6% more, counted in the fixed costs.
